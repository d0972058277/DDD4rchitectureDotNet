# 微服務關聯性識別碼 (Correlation ID) 完整指南

本函式庫為微服務架構提供全方位的關聯性識別碼支援，涵蓋多種通訊協議，實現端到端的分散式追蹤。

## 🎯 支援的通訊協議

| 協議 | 狀態 | 說明 |
|-----|------|-----|
| **HTTP/REST APIs** | ✅ 完整支援 | ASP.NET Core middleware、HttpClient 自動注入 |
| **gRPC** | ✅ 完整支援 | Client & Server interceptors |
| **RabbitMQ** | ✅ 完整支援 | IBasicProperties.Headers 處理 |
| **Kafka** | ✅ 完整支援 | Headers 與 Message 支援，byte[] 轉換 |
| **IceRPC** | ✅ 泛型支援 | 透過 IDictionary fallback 機制 |
| **自訂協議** | ✅ 可擴展 | 實作 ICorrelationProtocolHandler 介面 |

## 📦 核心架構

// 主要傳播介面

## 🚀 快速開始

### 1. 基本服務註冊

```csharp
// Program.cs 或 Startup.cs
services.AddCorrelation(options =>
{
    options.RequestHeader = "X-Correlation-ID";      // 請求標頭名稱
    options.IncludeInResponse = true;                 // 在回應中包含
    options.AddToLoggingScope = true;                 // 加入日誌作用域
    options.EnforceHeader = false;                    // 是否強制要求標頭
});

// 註冊 HTTP 中介軟體
app.UseCorrelation();
```

### 2. HTTP 支援配置

```csharp
// 註冊 HTTP 關聯性支援
services.AddHttpCorrelation();

// 配置具名 HTTP 客戶端
services.AddHttpClient<MyApiClient>(client =>
{
    client.BaseAddress = new Uri("https://api.example.com");
})
.AddCorrelationPropagation(); // 自動添加關聯性標頭

// 或全域配置所有 HTTP 客戶端
services.ConfigureAll<HttpClientFactoryOptions>(options =>
{
    options.HttpMessageHandlerBuilderActions.Add(builder =>
    {
        builder.AdditionalHandlers.Add(
            builder.Services.GetRequiredService<HttpCorrelationHandler>()
        );
    });
});
```

### 3. gRPC 支援配置

```csharp
// 註冊 gRPC 關聯性支援
services.AddGrpcCorrelation();

// 伺服器端：為 gRPC 服務添加攔截器
services.AddGrpc(options =>
{
    options.Interceptors.Add<GrpcCorrelationServerInterceptor>();
});

// 客戶端：配置 gRPC 客戶端攔截器
services.AddGrpcClient<MyGrpcService.MyGrpcServiceClient>(options =>
{
    options.Address = new Uri("https://grpc.example.com");
})
.AddInterceptor<GrpcCorrelationClientInterceptor>();
```

### 4. 訊息佇列支援配置

```csharp
// 註冊訊息佇列關聯性支援
services.AddMessagingCorrelation();

// RabbitMQ 和 Kafka 的 protocol handlers 會自動註冊
// 同時註冊整合輔助類別
```

## 🔄 使用範例

### HTTP 微服務呼叫鏈

```csharp
// 控制器中自動提取和設定關聯性上下文
[ApiController]
public class OrderController : ControllerBase
{
    private readonly IHttpClientFactory _httpClientFactory;
    private readonly ICorrelationService _correlationService;

    public OrderController(
        IHttpClientFactory httpClientFactory,
        ICorrelationService correlationService)
    {
        _httpClientFactory = httpClientFactory;
        _correlationService = correlationService;
    }

    [HttpPost]
    public async Task<IActionResult> CreateOrder([FromBody] CreateOrderRequest request)
    {
        // 關聯性 ID 已自動從請求標頭中提取並設定
        var correlationId = _correlationService.CorrelationId;
        
        // HTTP 客戶端會自動注入關聯性 ID
        var httpClient = _httpClientFactory.CreateClient("payment-service");
        var response = await httpClient.PostAsJsonAsync("/payments", new { OrderId = request.Id });
        
        return Ok();
    }
}
```

### RabbitMQ 發布/訂閱

```csharp
// 發布者
public class OrderEventPublisher
{
    private readonly IConnection _connection;
    private readonly RabbitMqCorrelationIntegration _correlationIntegration;

    public OrderEventPublisher(
        IConnection connection, 
        RabbitMqCorrelationIntegration correlationIntegration)
    {
        _connection = connection;
        _correlationIntegration = correlationIntegration;
    }

    public void PublishOrderCreated(OrderCreatedEvent orderEvent)
    {
        using var channel = _connection.CreateModel();
        var properties = channel.CreateBasicProperties();
        
        // 注入關聯性 ID 到訊息屬性
        _correlationIntegration.InjectCorrelationId(properties);
        
        var body = JsonSerializer.SerializeToUtf8Bytes(orderEvent);
        channel.BasicPublish("orders", "order.created", properties, body);
    }
}

// 消費者
public class OrderEventConsumer
{
    private readonly RabbitMqCorrelationIntegration _correlationIntegration;
    private readonly ICorrelationContextFactory _correlationFactory;

    public void HandleMessage(BasicDeliverEventArgs args)
    {
        // 提取並建立關聯性上下文
        using var correlationContext = _correlationIntegration.CreateCorrelationContext(
            args.BasicProperties, _correlationFactory);
        
        var orderEvent = JsonSerializer.Deserialize<OrderCreatedEvent>(args.Body.Span);
        ProcessOrder(orderEvent); // 關聯性上下文可用於整個處理過程
    }
}
```

// 發布者
public class PaymentEventProducer

### 手動協議處理

```csharp
public class CustomProtocolService
{
    private readonly ICorrelationPropagator _propagator;

    public CustomProtocolService(ICorrelationPropagator propagator)
    {
        _propagator = propagator;
    }

    public void HandleCustomProtocol()
    {
        // 支援任何實作 IDictionary 的元數據容器
        var metadata = new Dictionary<string, string>();
        
        // 注入關聯性 ID
        _propagator.Inject(metadata);
        
        // 提取關聯性 ID
        var correlationId = _propagator.Extract(metadata);
        
        // 也支援其他字典類型
        var objectDict = new Dictionary<string, object>();
        _propagator.Inject(objectDict);
    }
}
```

## 🛠️ 高級功能

### 錯誤關聯追蹤

```csharp
public class GlobalExceptionHandler
{
    private readonly ICorrelationService _correlationService;
    private readonly ILogger<GlobalExceptionHandler> _logger;

    public async Task HandleAsync(HttpContext context, Exception exception)
    {
        var correlationId = _correlationService.CorrelationId;
        
        // 在結構化日誌中包含關聯性 ID
        _logger.LogError(exception, 
            "發生未處理的例外狀況。關聯性ID: {CorrelationId}", 
            correlationId);
        
        // 在錯誤回應中返回關聯性 ID 以便客戶端關聯
        context.Response.Headers["X-Correlation-ID"] = correlationId.ToString();
        
        await context.Response.WriteAsync(JsonSerializer.Serialize(new 
        {
            Error = "內部伺服器錯誤",
            CorrelationId = correlationId,
            Timestamp = DateTime.UtcNow
        }));
    }
}
```

### 分散式追蹤情境

```
API Gateway → 訂單服務 → 付款服務 → 庫存服務 → 通知服務
    ↓           ↓           ↓           ↓           ↓
  生成 ID     HTTP       gRPC      RabbitMQ     Kafka
            傳播        傳播        傳播        傳播
```

每個服務會自動：
1. 從傳入請求中提取關聯性 ID
2. 為請求範圍設定關聯性上下文
3. 將關聯性 ID 注入到所有外發呼叫
4. 在結構化日誌中包含關聯性 ID

### 自訂協議支援

```csharp
// 實作自訂協議處理器
public class MyCustomProtocolHandler : ICorrelationProtocolHandler
{
    public Type MetadataType => typeof(MyCustomMetadata);

    public void Inject(object metadata, string headerName, string correlationId)
    {
        if (metadata is MyCustomMetadata customMetadata)
        {
            customMetadata.Headers[headerName] = correlationId;
        }
    }

    public string? Extract(object metadata, string headerName)
    {
        if (metadata is MyCustomMetadata customMetadata)
        {
            return customMetadata.Headers.TryGetValue(headerName, out var value) ? value : null;
        }
        return null;
    }
}

// 註冊自訂處理器
services.AddTransient<ICorrelationProtocolHandler, MyCustomProtocolHandler>();
```

## ⚙️ 配置選項

```csharp
services.AddCorrelation(options =>
{
    // 標頭配置
    options.RequestHeader = "X-Correlation-ID";          // 預設: "X-Correlation-ID"
    options.ResponseHeader = "X-Response-Correlation";   // 預設: 與 RequestHeader 相同
    
    // 行為選項
    options.IgnoreRequestHeader = false;                 // 預設: false
    options.EnforceHeader = true;                        // 預設: false (缺少時返回 400)
    options.IncludeInResponse = true;                    // 預設: true
    options.UpdateTraceIdentifier = true;               // 預設: false
    
    // 日誌整合
    options.AddToLoggingScope = true;                    // 預設: false
    options.LoggingScopeKey = "CorrelationId";          // 預設: "CorrelationId"
    
    // 自訂 ID 生成
    options.CorrelationIdGenerator = () => $"custom-{Guid.NewGuid():N}";
});
```

## 📊 效能考量

### 記憶體使用
- **AsyncLocal 儲存**: 執行緒安全的上下文儲存
- **物件池化**: HTTP handler 和 interceptor 重複使用
- **最小配置**: 僅在需要時分配物件

### 效能影響
- **HTTP**: 每個請求約 1-2ms 額外開銷
- **gRPC**: 每個呼叫約 0.5-1ms 額外開銷  
- **訊息佇列**: 每個訊息約 0.1-0.5ms 額外開銷

### 最佳實踐
1. **使用依賴注入**: 避免直接建立實例
2. **配置適當的標頭名稱**: 避免與現有標頭衝突
3. **監控日誌輸出**: 確保關聯性 ID 正確傳播
4. **測試分散式情境**: 驗證端到端追蹤

## 🔍 疑難排解

### 常見問題

**Q: 關聯性 ID 沒有在服務間傳播？**
A: 檢查：
- 是否正確註冊了協議特定的支援 (`AddHttpCorrelation()`, `AddGrpcCorrelation()`)
- HTTP 客戶端是否配置了 `.AddCorrelationPropagation()`
- gRPC 客戶端是否添加了攔截器

**Q: 日誌中沒有關聯性 ID？**
A: 確保：
- 設定 `options.AddToLoggingScope = true`
- 使用結構化日誌 (如 Serilog、NLog)
- 檢查日誌範本是否包含關聯性 ID 欄位

**Q: RabbitMQ/Kafka 訊息沒有關聯性 ID？**
A: 驗證：
- 調用了 `services.AddMessagingCorrelation()`
- 使用了整合類別 (`RabbitMqCorrelationIntegration`, `KafkaCorrelationIntegration`)
- 正確注入和提取關聯性 ID

### 除錯工具

```csharp
// 中介軟體除錯
public class CorrelationDebugMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<CorrelationDebugMiddleware> _logger;

    public async Task InvokeAsync(HttpContext context, ICorrelationService correlationService)
    {
        var incomingCorrelationId = context.Request.Headers["X-Correlation-ID"].FirstOrDefault();
        var currentCorrelationId = correlationService.CorrelationId;
        
        _logger.LogDebug("傳入關聯性ID: {IncomingId}, 當前關聯性ID: {CurrentId}", 
            incomingCorrelationId, currentCorrelationId);
        
        await _next(context);
    }
}
```
